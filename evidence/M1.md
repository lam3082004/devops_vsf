## Luồng pull — không có secret nào ở giữa

```
App Service (slot staging)
   │ 1. xin token của user-assigned MI qua IMDS của instance
   ▼
Entra ID ──► access token cho id-vsf-app-c2021f
   │                 (client_id 8a0a974c-a19e-465b-a837-e79ceebafe9a)
   │ 2. đổi lấy ACR refresh/access token
   ▼
ACR data plane  acrvsfc2021f.azurecr.io
   │ 3. RBAC: principal 88d362ec-…f443104 có AcrPull trên chính ACR này?
   ▼
   đạt → trả layer image → container khởi động
```

Ba điểm làm nên M1:
- **Client ID phải khai rõ.** Bỏ trống thì nền tảng đi tìm system-assigned identity — Web App này không bật → pull `unauthorized`.
- **Token là data plane, không phải control plane.** Quyền `Reader`/`Contributor` trên ARM không cho kéo image; phải là `AcrPull` (data action `…/registries/pull/read`).
- **Token ngắn hạn, tự xoay vòng.** Không có username/password nào nằm trong app settings để rò rỉ hay phải đổi định kỳ.

## Đẩy image bằng danh tính Entra (không dùng admin)

```
az acr login -n acrvsfc2021f                    → Login Succeeded  (token Entra)
docker build --platform linux/amd64 \
  --build-arg GIT_SHA=c710815 \
  -t acrvsfc2021f.azurecr.io/vsf-app:c710815 app/
docker push acrvsfc2021f.azurecr.io/vsf-app:c710815
  → c710815: digest: sha256:9dca8e0c…d3315 size: 1864
```

Không dùng `--username/--password`, không bật admin user. Tài khoản vận hành là
Owner trên subscription nên đủ quyền push; **không** phải thêm role `AcrPush`.
`--platform linux/amd64` là bắt buộc: image build trên ARM sẽ thoát ngay trên
App Service với lỗi định dạng (bẫy trong guide).

Đặt image cho slot staging (làm tay ở bài này; D16 sẽ tự động):

```
az webapp config container set -g rg-vsf-dev -n app-vsf-c2021f --slot staging \
  --container-image-name acrvsfc2021f.azurecr.io/vsf-app:c710815 \
  --container-registry-url https://acrvsfc2021f.azurecr.io
```

Đã kiểm lại sau lệnh này: cờ MI và client ID **vẫn còn** (lo ngại lệnh ghi đè
cấu hình identity là không xảy ra).

## Chứng minh ngược — gỡ AcrPull thì app không pull được (D12, 2026-09-23)

**Lần thử đầu thất bại, và chính nó mới là bài học.** Sau khi gỡ role bằng
`terraform apply -var 'grant_app_acr_pull=false'` (`0 added, 0 changed, 1 destroyed`)
rồi `az webapp restart`, app **vẫn trả 200**:

```
08:35:37 200   08:35:38 200   08:35:39 200 …
```

Lý do: image `vsf-app:f38c127` đã nằm sẵn trên worker. Restart **không buộc pull lại** —
worker dùng bản cache. Mất quyền pull không đụng được tới container đang có image.

Đây đúng là bài học của M5 lặp lại ở tầng khác: **thu hồi quyền không tự làm gãy thứ đang
chạy**; phải tạo ra tình huống thật sự cần quyền đó.

**Cách ép pull:** đẩy một tag mới (worker chưa từng thấy) rồi trỏ app sang tag đó.

```
docker tag  …/vsf-app:f38c127  …/vsf-app:acrpull-test
docker push …/vsf-app:acrpull-test      → digest sha256:91a8e99c…fe39e
az webapp config container set … --container-image-name …/vsf-app:acrpull-test
```

Kết quả ngay sau đó — **503**, liên tục:

```
08:36:53 503   08:37:19 503   08:37:24 503 …
```

Log khởi động (`evidence/raw/d12-m1-acrpull-denied-2026-09-23.log`):

```
ContainerStatus: Pulling image: acrvsfj124ze.azurecr.io/vsf-app:acrpull-test.
LastError: ACRTokenRetrievalFailure
LastErrorDetails: Could not resolve the ACR token with the specified managed identity
                  due to the following: Fetching Acr token failed -- response status
                  indicates failure. Status Code:Unauthorized
Site container: app-vsf-j124ze terminated during site startup. Cancelling site startup.
```

`ACRTokenRetrievalFailure` … `Status Code:Unauthorized` nói chính xác điều M1 cần chứng minh:
nền tảng **vẫn dùng đúng managed identity đã khai** (không rơi về admin user, vì admin user đã
tắt), nhưng identity đó không còn `AcrPull` nên không đổi được token data plane của ACR.

**Trả quyền:** `terraform apply` → `1 added, 0 changed, 0 destroyed` (role tạo lại sau 29s) →
`az webapp restart` → app **200** trở lại, `/version` = `{"sha":"f38c127"}`, và lúc này nó đang
chạy **đúng tag `acrpull-test` vừa pull hỏng lúc nãy**. Cùng một image, cùng một worker, chỉ
khác có quyền hay không — cặp before/after sạch.

`terraform plan` sau cùng: **`No changes. Your infrastructure matches the configuration.`**
(`evidence/raw/d12-plan-final-2026-09-23.log`) — không còn drift.

Tag `acrpull-test` chỉ tồn tại để đo; môi trường đã `make down` ngay sau đó nên ACR cũng mất theo.

## Tự kiểm tra (trả lời bằng lời khi mentor hỏi)

1. **Vì sao phải chỉ định client ID?** Web App có thể gắn nhiều user-assigned identity; nền tảng không tự đoán dùng cái nào. Bỏ trống = dùng system-assigned, mà site này không bật → pull `unauthorized`.
2. **Token lấy ở đâu, gửi tới đâu?** Lấy từ Entra ID qua IMDS của instance, đổi sang ACR token, rồi gửi tới **data plane** `acrvsfc2021f.azurecr.io`. Không đụng control plane ARM, nên `Reader` trên ARM vô dụng ở đây.
3. **Bật lại admin user thì sai ở đâu dù app vẫn chạy?** Admin user là cặp username/password tĩnh, dùng chung, không gắn với danh tính ai, không xoay vòng và không thu hồi riêng lẻ được. Nó mở một đường vào ACR song song nằm ngoài RBAC — M1 đòi pull **bằng identity**, nên chỉ cần tồn tại đường đó là vi phạm, kể cả khi không ai dùng.
4. **Vì sao `docker_registry_url` cũng phải `ignore_changes`?** Lần dựng từ rỗng, ACR chưa có image nào; nếu Terraform khai registry = ACR thì Web App pull một image không tồn tại → 503 ngay từ `make up`. Giữ MCR làm placeholder, rồi tay/CD chuyển sang ACR; thiếu `ignore_changes` thì apply kế tiếp kéo ngược về placeholder và sập bản đang chạy.
