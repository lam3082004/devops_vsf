Cơ chế (suy luận từ tài liệu Microsoft về MySQL Flexible Server + Entra, **chưa thử cấp quyền thật** — bước 4 của probe chỉ liệt kê service principal Graph): MySQL Flexible Server bật Entra phải gắn một user-assigned identity cho **server**, và identity đó cần quyền Microsoft Graph (đọc thư mục để ánh xạ
người dùng/identity). Cấp quyền Graph application cho identity cần Privileged Role Administrator hoặc Global Administrator của tenant — tài khoản này không có và
không tự tạo được app (`allowedToCreateApps=false`, cùng nguyên nhân với Q6 trong plan).

## Hiện trạng thay thế và rủi ro còn lại
App kết nối bằng tài khoản admin MySQL; mật khẩu sinh bằng `random_password`, sống trong Key Vault, đọc qua Key Vault reference bằng MI (M4/M5). Rủi ro: nếu có SQLi thì
toàn quyền server (`known-issues.md` #33 mục 3).

## Nếu có đủ quyền thì làm
1. Tạo user-assigned identity cho server MySQL; nhờ admin tenant cấp Graph `User.Read.All`, `GroupMember.Read.All`, `Application.Read.All`.
2. Gắn identity vào server, đặt Entra administrator (`azurerm_mysql_flexible_server_active_directory_administrator`).
3. Đặt `authConfig` cho phép Entra; giữ mật khẩu tới khi chuyển xong.
4. Tạo user MySQL ánh xạ MI của `be` với quyền tối thiểu trên DB `opsboard` (không dùng admin).
5. `be` lấy token Entra làm mật khẩu (không còn `DB_PASSWORD`); thêm test.
6. Bỏ secret mật khẩu khỏi app settings; kiểm M5 lại.
7. Chứng minh: gỡ quyền MI → `/items` gãy.
