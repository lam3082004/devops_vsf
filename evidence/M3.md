## Đường đi của một request `/items`

```
curl  ──►  App Service (Central India)
              │ 1. đọc DB_HOST/DB_NAME/DB_USER từ app settings
              │    đọc DB_PASSWORD qua Key Vault reference (xem M5)
              ▼
           kết nối ra ngoài bằng MỘT trong các outbound IP của plan
              │ 2. MySQL Flexible Server (Southeast Asia) nhận kết nối
              │    kiểm tra IP nguồn có trong firewall rule không
              ▼
           TLS bắt buộc (DB_TLS=true) ──► xác thực user/mật khẩu
              ▼
           đọc/ghi bảng ──► trả JSON
```

Ba điểm cần hiểu:

- **Phải allowlist `possibleOutboundIpAddresses`, không phải `outboundIpAddresses`.**
  `outboundIpAddresses` là các IP app đang dùng *lúc này*; `possibleOutboundIpAddresses`
  là **toàn bộ** IP app có thể dùng khi Azure chuyển nó sang worker khác trong cùng
  scale unit (scale out, restart, bảo trì nền tảng). Chỉ mở tập nhỏ thì app chạy được
  hôm nay và lỗi kết nối ngẫu nhiên vào hôm khác — loại lỗi rất khó truy. `infra/app/db.tf:76`
  dùng `for_each` trên `possible_outbound_ip_address_list` đúng vì lý do này.
- **App và DB khác region** (Central India ↔ Southeast Asia) do subscription bị chặn
  tạo MySQL Flexible ở Central India — xem Decisions trong plan. Đánh đổi: thêm vài
  chục ms mỗi query.
- **Không bật "Allow public access from any Azure service"**. Cờ đó mở cho *mọi*
  subscription Azure của *mọi* khách hàng, không phải chỉ của mình — rộng hơn rất
  nhiều so với việc liệt kê 20 IP.

## Lệnh lấy từng ô

```bash
TF="terraform -chdir=infra/app"
URL=$($TF output -raw app_url)                       # https://app-vsf-xxxxxx.azurewebsites.net
APP=$(echo "$URL" | sed 's|https://||; s|\..*||')    # app-vsf-xxxxxx
MYSQL=$($TF output -raw mysql_fqdn | sed 's|\..*||') # mysql-vsf-xxxxxx

# ô 1
curl -s -w '\n%{http_code}\n' "$URL/health"

# ô 2 — tên có timestamp để biết bản ghi thuộc lần đo nào
TS=$(date +%H%M%S)
curl -s -w '\n%{http_code}\n' -X POST "$URL/items" \
  -H 'content-type: application/json' -d "{\"name\":\"d12-check-$TS\"}"

# ô 3
curl -s -w '\n%{http_code}\n' "$URL/items"

# ô 5-8 — hai số dưới đây phải BẰNG NHAU
az mysql flexible-server firewall-rule list -g rg-vsf-dev -n "$MYSQL" -o table
az mysql flexible-server firewall-rule list -g rg-vsf-dev -n "$MYSQL" --query "length(@)"
$TF output -raw app_possible_outbound_ip_count       # output đã có sẵn đúng cho M3
```

## Hạn chế của cách chặn theo outbound IP

Outbound IP của App Service **dùng chung cho cả scale unit**, không riêng app này.
Một app của khách hàng khác nằm cùng scale unit sẽ đi ra bằng đúng những IP đó, nên
firewall này không phân biệt được "app của tôi" với "app cùng stamp". Nó chặn được
Internet nói chung, không chặn được hàng xóm trong cùng hạ tầng — muốn chặn thật thì
cần Private Endpoint, đưa MySQL vào VNet và tắt hẳn public access (S3 trong `topic.md`).
