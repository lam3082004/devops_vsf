## Lease mồ côi trên `app.tfstate` (18:12) — CHƯA GỠ

Khác với 4 lần đứt mạng ở D10 (lease đều **tự nhả**), lần này lease **không nhả**:

```
az storage blob show --account-name stvsftffxqfgb --container-name tfstate \
  --name app.tfstate --auth-mode login --query "properties.lease"
→ {"duration": "infinite", "state": "leased", "status": "locked"}

--query "metadata"  → {}          (rỗng!)
```

Đọc được gì từ hai giá trị này: Terraform đã **xoá xong metadata lock** nhưng
lệnh `Put` để **nhả lease thì đứt** — nên còn lại một lease vô thời hạn không
gắn với lock ID nào. Hệ quả:

- `terraform force-unlock <ID>` **không dùng được**: không còn ID để truyền.
- Lease `infinite` **không tự hết hạn** — khác lease có thời hạn.
- Mọi lệnh Terraform sau đó, **kể cả `make down`**, sẽ treo ở "Acquiring state lock".

Đã xác nhận không có tiến trình nào đang chạy: `pgrep -af terraform` chỉ ra
`terraform-ls` (language server của VS Code), không phải `plan`/`apply`.

Cách gỡ (phải người dùng chạy — Claude Code chặn với lý do `Modify Shared Resources`):

```
az storage blob lease break --account-name stvsftffxqfgb \
  --container-name tfstate --blob-name app.tfstate --auth-mode login
```

Bổ sung cho quy trình "đứt giữa chừng" ở `notes/d10.md`: bước 3 nói dùng
`force-unlock`, nhưng nó chỉ đúng khi **metadata còn lock ID**. Nếu metadata đã
rỗng mà lease vẫn `leased` thì phải `lease break` ở tầng blob.

Mạng lúc 18:10–18:15 lỗi 3 lần liên tiếp (`terraform plan`, `az rest`,
`az storage blob show` timeout) — cùng dạng với `known-issues.md` #7. **Kiểm
Cloudflare WARP trước khi chạy `make down`**: destroy đứt giữa chừng đắt hơn
nhiều so với plan đứt.
