## Pha B — OpenTelemetry trong `be` (PR #59)

- `Azure.Monitor.OpenTelemetry.AspNetCore` **1.6.0** (stable mới nhất, 27/07/2026) → kéo OpenTelemetry 1.15.x,
  Azure.Core, MSAL. `Infrastructure/Telemetry.cs`: chỉ bật khi có connection string; nếu vẫn là tham chiếu
  Key Vault chưa resolve → **tắt + cảnh báo**, không thoát (khác `DB_PASSWORD`: mất trace không đáng làm
  sập app).
- **Kế hoạch nói sai 2 chỗ** (`ai-failure-log.md` #36, #37):
  1. "`throw` không bắt → 500 body rỗng": thật ra `DatabaseExceptionFilter` bắt mọi exception → **503**.
     Sửa: `BoomException` + `BoomExceptionFilter` (500 `boom`, log error, `Activity.AddException`).
  2. "Sampling 100% là mặc định": distro ≥ 1.5.0 mặc định **5 trace/giây** → đặt `SamplingRatio = 1`,
     `TracesPerSecond = null`. Và C1 gắn workspace vào cờ App Insights — mâu thuẫn "D21 dùng lại workspace".
- Sampler `ParentBased` với `localParentNotSampled = AlwaysOff` (còn lại AlwaysOn): span SQL của `/health`
  (request đã bị lọc) không ra thành dependency mồ côi; request ngoài mang traceparent `-00` vẫn được trace
  (lần đầu viết `ParentBased(AlwaysOn)` → sẽ bỏ các request đó; tự review bắt được trước PR).
- `span_id` trong log request. Không export log qua OpenTelemetry (lọc provider về `None`).
- Kiểm: `make test` 137 pass/12 skip (test mới `TracingTests`), `make lint` sạch; chạy local không connection
  string (B6) và có connection string giả → ingestion endpoint giả, trong docker cùng MySQL 8.4 thật:
  `evidence/raw/d20-otel-local-docker*.{jsonl,log}`. Máy này host **không** vào được mạng bridge docker
  (`No route to host` tới 172.17.0.2; `make test-db` cũng đỏ trên `main` vì lý do đó — không phải code),
  nên `docker build --network host` và chạy mọi thứ trong một network docker riêng.
- Trivy image `be` (190 MB, +6 MB): phần .NET 0 CVE; cổng CRITICAL/HIGH exit 0.
