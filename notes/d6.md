## Bước 2 — Commit đầu tiên

```bash
git status --short | head -20

git commit -m "chore: khung dự án — app Rust, docs, notes, evidence D1–D5"
```

**Xong khi:** `git log --oneline` có 1 commit, `git show --stat` không chứa `target/`, `.env.local`.

## Bước 3 — Tạo repo private và push

```bash
gh repo create devops-vsf --private --source=. --remote=origin --description "Internship: Azure App Service + CI/CD + monitoring"
git push -u origin main
gh repo view --web
```

**Xong khi:** repo hiện trên GitHub, nhánh `main` có commit. Đây là **lần push thẳng `main` duy nhất** — từ bước 5 trở đi bị cấm.

## Bước 4 — Cài đặt merge

`Settings → General → Pull Requests`:
- ✅ Allow squash merging · ❌ Allow merge commits · ❌ Allow rebase merging
- ✅ Automatically delete head branches

Lý do: squash-only giữ lịch sử `main` mỗi commit = một PR → revert một PR là revert một commit.

## Bước 5 — Ruleset `protect-main` (mục quan trọng nhất)

`Settings → Rules → Rulesets → New branch ruleset`:

| Mục | Giá trị |
|---|---|
| Name | `protect-main` |
| Enforcement status | **Active** |
| Bypass list | **để trống** — kể cả admin (đề bài: "kể cả khi làm một mình") |
| Target branches | Include **default branch** |
| Restrict deletions | ✅ |
| Require linear history | ✅ |
| Require a pull request before merging | ✅ · Required approvals **0** (làm một mình) |
| Block force pushes | ✅ |
| Require status checks | **để trống lúc này** — quay lại ở bước 10 sau khi CI chạy lần đầu |

**Kiểm chứng ngay (bằng chứng M9 phần 1):**
```bash
echo "test" >> README.md && git add -A && git commit -m "test: thu push thang main"
git push origin main        # PHẢI BỊ TỪ CHỐI
git reset --hard HEAD~1     # hoàn tác commit thử
```
Chụp output bị từ chối → `evidence/d06/screenshots/`.

⚠️ Nếu push **thành công** ⇒ ruleset không được cưỡng chế ⇒ tài khoản không phải Pro ⇒ dừng, báo mentor.

## Bước 6 — Pre-commit hook gitleaks

```bash
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
gitleaks protect --staged --redact -v || {
  echo "gitleaks: phat hien secret trong staged changes — commit bi chan"
  exit 1
}
EOF
chmod +x .git/hooks/pre-commit
```

**Kiểm chứng:** tạo file chứa chuỗi khoá giả (lấy mẫu từ test fixtures của gitleaks, **không dùng khoá thật**) → `git add` → `git commit` → phải bị chặn. Chụp lại rồi xoá file thử.

Ghi chú: hook nằm trong `.git/` nên **không theo repo**. Người clone mới phải tự cài → ghi vào README ở D24. Đây cũng là lý do CI phải quét lại (bước 8).

## Bước 7 — PR template

`.github/pull_request_template.md` gồm 4 mục: **Tóm tắt** · **AI usage** · **Bằng chứng** (lệnh đã chạy, link CI run) · **Checklist** (không secret, đã chạy `make check`, đã cập nhật docs/evidence).

## Bước 8 — CI v1

`.github/workflows/ci.yml`, trigger `pull_request` vào `main`, quyền token chỉ đọc:

| Job | Nội dung | Đỏ khi |
|---|---|---|
| `gitleaks` | checkout **fetch-depth: 0** (toàn bộ lịch sử) → quét | có secret |
| `rust` | `cargo fmt --check` · `cargo clippy -- -D warnings` · `cargo test` | sai format / cảnh báo / test fail |
| `terraform` | `fmt -check` · `init -backend=false` · `validate` | sai cú pháp (thư mục `infra/` sẽ có ở D7) |

Nguyên tắc: ghim version action theo tag/SHA · cache `~/.cargo` và `app/target` · nhóm đồng thời theo PR, huỷ run cũ khi có commit mới · **không** dùng `continue-on-error` cho bước quét.

## Bước 9 — PR thật đầu tiên

```bash
git switch -c chore/ci-v1
# thêm .github/workflows/ci.yml + pull_request_template.md
git add -A && git commit -m "ci: them CI v1 (gitleaks, rust fmt/clippy/test, terraform validate)"
git push -u origin chore/ci-v1
gh pr create --fill
gh pr checks --watch
```

**Xong khi:** cả 3 job xanh, merge bằng squash.

## Bước 10 — Required status checks

Quay lại ruleset → **Require status checks to pass** → thêm đúng tên 3 job (tên chỉ hiện sau khi workflow chạy ít nhất một lần) → Save. Chụp màn hình.

## Bước 11 — Bằng chứng đỏ (M9)

```bash
git switch -c test/red-secret
# thêm file chứa chuỗi khoá giả; tạm bỏ qua hook local: git commit --no-verify
git push -u origin test/red-secret && gh pr create --fill
```
Cần chụp **2 ảnh**:
1. Tab Checks: job `gitleaks` **đỏ**
2. Khung merge: nút bị khoá, ghi "Required statuses must pass"

Rồi: đóng PR, xoá nhánh, kiểm tra `main` không dính commit nào chứa secret giả.
